# MediFlow CRM — معمارية التوسع المستقبلي للعيادات المتعددة (Future Multi-Clinic Architecture)

## 1. الرؤية المستقبلية
تم تصميم مخطط قاعدة البيانات ونموذج الصلاحيات في الإصدار الأول بحيث يكون مهيأً للتوسع إلى منصة سحابية متعددة المستأجرين (Multi-Tenant SaaS) تتيح استضافة عدة عيادات ومراكز طبية مستقلة تماماً.

## 2. عناصر العزل المجهزة حالياً (Ready Isolation Primitives)
- **معرف العيادة الإلزامي (`clinic_id`):** موجود في كافة الجداول الأساسية (`patients`, `appointments`, `services`, `payments`, `visits`, `whatsapp_conversations`).
- **سياسات الأمان على مستوى الصفوف (Row Level Security):** دالة `current_user_has_clinic_access(clinic_id)` تمنع وصول أي مستخدم إلى بيانات عيادة أخرى على مستوى محرك قاعدة البيانات نفسه.
- **جدول عضويات العيادات (`clinic_memberships`):** يتيح ربط حساب المستخدم الواحد بعدة عيادات بأدوار مختلفة في المستقبل.

## 3. خطوات الترقية إلى Multi-Tenant SaaS
1. **محدد العيادة (Tenant Switcher):** إضافة قائمة منسدلة في الشريط العلوي للمستخدمين الذين يملكون صلاحيات في أكثر من عيادة.
2. **النطاقات الفرعية (Subdomains):** تفعيل توجيه النطاقات مثل `dr-ali.mediflow.app` وربطه بالعيادة عبر حقل `subdomain` في جدول `clinics`.
3. **فصل حسابات WhatsApp Cloud API:** ربط كل عيادة بـ `phone_number_id` وتوكن خاص بها في جدول `clinic_settings`.
4. **نظام الاشتراكات والفوترة:** إضافة جدول `subscriptions` وخطة تسعير لكل عيادة حسب عدد الأطباء وسعة الرسائل الشهرية.
